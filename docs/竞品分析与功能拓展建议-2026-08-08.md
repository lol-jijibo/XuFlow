## 三、存在的核心问题（按严重度排序）

### P0 — 影响基本可用性 / 正确性

1. **数据库路径硬编码**：`desktop/src-tauri/src/lib.rs` 中 SQLite 路径写死为 `D:\Projects-star\Xuflow\...`，换机器/分发后直接不可用。这是 release blocker。
2. **上下文裁剪是"丢弃式"**：超 80% 直接丢旧轮次，Agent 会"失忆"——忘记用户早前需求，导致长任务翻车。主流产品全部用 LLM 摘要压缩保留关键信息。
3. **edit 工具过于脆弱**：精确字符串替换对模型要求极高（空格/缩进不匹配即失败），是工具失败率的主要来源。Aider 的 diff/edit format 和 Claude Code 的 apply_patch 都证明这是核心体验点。
4. **测试几乎为零**：Agent 循环、工具、MCP、SQLite 均无测试。core 是"唯一真相源"，没有测试网保护，改一处坏两端。

### P1 — 影响竞争力

5. **无代码索引/RAG**：vector.rs 是空壳。没有 repo map 或语义索引，大项目里 Agent 只能靠 grep 盲找，上下文利用率低。这是 Cursor/Aider 的核心卖点。
6. **无检查点/回滚机制**：Agent 改坏文件后只能靠 git 手动救。Claude Code 的 checkpoint + rewind 是用户敢于放手让 Agent 干活的前提。
7. **CLI 与桌面端能力不对称**：CLI 只注册了基础工具（无 edit/git/todo/glob），违背"一处编写双端生效"的设计初衷。
8. **无 Skill/规则文件机制**：没有 CLAUDE.md / .cursor/rules 式的项目级约定注入，也没有可复用的 skill 包。Agent 行为无法按项目定制。

### P2 — 影响体验与生态

9. **无 slash 命令体系**：`/commit`、`/review`、`/compact` 这类快捷指令是 CLI 类产品的效率核心。
10. **无多模态**：不能拖截图进去让它改 UI，桌面端场景下尤其可惜。
11. **无费用统计**：只有 token 数，用户无法感知成本。
12. **托盘是 stub、无自动更新**：`tray.rs` 是 TODO，Tauri updater 未接。README 里宣传的托盘功能实际没落地。
13. **MCP 仅 stdio**：远程 MCP server（SSE/Streamable HTTP）是趋势，只支持本地 stdio 会错过大量生态。

## 四、可拓展的功能方向（建议路线图）

### Phase 1：补齐正确性底座（2-3 周）

- **修复数据库路径**：改用 `tauri::path::AppDataDir` 动态获取，支持迁移已有库
- **LLM 摘要式上下文压缩**：超阈值时对旧轮次生成摘要替代丢弃（复用现有 backend，成本低收益大）
- **edit 工具升级**：增加 `apply_patch`（unified diff 格式）+ 模糊匹配回退（忽略尾随空白、缩进归一化）
- **core 测试套件**：Agent 循环用 mock backend 测状态机；工具层做临时目录集成测试；目标 60% 覆盖

### Phase 2：差异化竞争力（3-4 周）

- **检查点系统**：每次 write/edit/bash 前自动快照（git stash 或影子目录 `.xuflow/checkpoints/`），支持一键 rewind 到任意轮
- **代码索引 v1**：不用急着上向量库——先做 **repo map**（Aider 路线：tree-sitter 提取符号 + PageRank 排序），纯 Rust 实现，一次编写双端生效，性价比远高于向量检索
- **XUFLOW.md 项目规则**：类似 CLAUDE.md，启动时自动注入系统提示词；支持全局 `~/.xuflow/XUFLOW.md` 分层
- **slash 命令 + 自定义命令**：`/commit` `/review` `/compact` `/init`（扫描项目生成 XUFLOW.md），用户可在 `.xuflow/commands/*.md` 自定义

### Phase 3：生态与高级能力（4 周+）

- **Subagent**：Task 工具派生子代理处理独立子任务（探索、并行搜索），主上下文不被污染
- **Hooks**：PreToolUse / PostToolUse / SessionStart 钩子，让用户能接格式化、lint、通知
- **多模态输入**：桌面端拖图/截图 → base64 图片消息（DeepSeek/Kimi 均有视觉模型）
- **MCP SSE/HTTP transport**：接入远程 MCP 生态
- **自动更新 + 托盘补全**：tauri-plugin-updater，兑现 README 承诺
- **后台任务/定时调度**：结合桌面端常驻特性做"每天早上跑 X 任务"的自动化（这是你双端 + 托盘常驻架构的天然优势，Claude Code 做不到）

### Phase 4：可选前沿

- 向量索引（usearch/sqlite-vec，本地嵌入模型）
- 多模型路由（按任务复杂度自动选模型，省成本）
- Web 端 / 远程模式（core 已是纯库，套一层 axum 即可 headless 运行）

## 五、值得借鉴的具体设计

### 从 Claude Code 借鉴

1. **CLAUDE.md 分层记忆**：项目级 + 用户级 + 会话级约定注入，实现成本极低（读文件拼进 system prompt），收益极高
2. **checkpoint + rewind**：用户敢放手的心理保障，也是"Agent 自主性"卖点的前提
3. **Skill 包机制**：可复用的工作流封装（SKILL.md + 脚本），是社区生态的起点
4. **TodoWrite 透明化**：你已做了一半（todo_write 工具），把任务列表在 UI 上做成常驻面板会更有"可控感"

### 从 Cursor 借鉴

5. **@ 引用语法**：`@文件` `@文件夹` `@符号` 显式圈定上下文，比让 Agent 自己 grep 精准得多
6. **Tab 补全 / Apply 按钮**：AI 建议的 diff 以可视化方式逐块接受/拒绝（你的 Git Review 面板已有雏形，可泛化到所有 edit）

### 从 Aider 借鉴

7. **Repo map**：tree-sitter + PageRank 生成仓库符号地图注入上下文，rust 生态有 tree-sitter 绑定，与 monorepo 架构完美契合
8. **自动提交**：每轮 Agent 修改后自动 git commit（可配置），天然获得回滚历史

### 从 Cline 借鉴

9. **Plan / Act 双模式切换**：你的 propose_plan 已有雏形，升级为完整 Plan 模式（只读探索 → 计划审批 → 执行）是低成本高感知的功能
10. **diff 视图内嵌聊天**：编辑直接在对话流里以 diff 高亮展示

### 从 Gemini CLI 借鉴

11. **慷慨的免费层策略 + 内置 Google 搜索 grounding**：考虑内置一两个免费搜索源（你已用 Tavily，需要 API key，是注册摩擦点）

## 六、一句话总结

> 架构底子（Rust core 一次编写双端生效 + MCP + Git 集成）在同类个人项目里属于上乘；
> 当前最大的短板不是功能数量，而是 **上下文管理（丢弃式裁剪）、编辑可靠性（字符串替换）、可回滚性（无 checkpoint）** 这三个"正确性底座"，以及 **XUFLOW.md / slash 命令** 这类低成本高感知的生态入口。
> 建议按 Phase 1 → 2 的顺序推进，避免在底座不稳时堆功能。
